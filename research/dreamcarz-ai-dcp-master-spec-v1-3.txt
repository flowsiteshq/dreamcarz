1. Executive Summary and North-Star Architecture
Dream Carz is to be implemented as one connected, event-driven mobility and economic platform. Membership,
vehicle access, rental pricing, DCP, future-driver planning, ownership paths, Host/Partner economics, Associate
production, commissions, company revenue, company cost and AI recommendations must all resolve to
traceable source transactions and permanent ledger events.
    NORTH STAR: Start where you are. Drive what you need. Build toward what you want.

1.1 The AI layer
The AI Concierge is a transportation advisor, not a scripted salesperson. It diagnoses the customer's current
transportation method, current cost, immediate need, future need, budget, vehicle target and desired outcome.
It then recommends the lowest adequate Dream Carz path using live pricing, inventory, DCP and eligibility data.

1.2 The economic layer
The economic engine is authoritative. The AI and front end may explain results, but neither may independently
create balances, invent multipliers, override eligibility, or calculate a final transaction without the rules engine
and ledger.

1.3 The ledger principle
Every material action creates a permanent event, a source transaction and the corresponding financial and DCP
ledger entries. Do not store only the latest totals. All balances must be reproducible from transaction history.

1.4 Primary platform modules
     Identity and member account
     Membership catalog and benefit rules

5. DCP Earning and Bonus Engine
5.1 Base value and base earn rate
     CURRENT CORE RULE: 100 DCP = $1 face value. Each active 1× wallet earns 10 DCP per eligible $1
     of qualifying cash activity.

Qualifying cash activity currently includes approved membership dues and eligible base rental cash collected.
Taxes, deposits, tolls, tickets, damage, claims, refunds, chargebacks, non-commissionable pass-through charges
and other excluded categories must not generate DCP unless an administrator explicitly enables them.

5.2 Event-based earning
     on event PAYMENT_SETTLED:
      load member + active plan + good_standing
      determine eligible_cash_amount

5.3 Starting DCP
     Post only after enrollment payment and eligibility checks succeed.
     Post to DCPR only under the current architecture.
     Use a distinct source_type = membership_enrollment and source_id = enrollment transaction ID.
     If enrollment is reversed/refunded, reverse the DCP through a new ledger transaction; never edit the original
      award.

5.5 Renewal timing rule
     A successful renewal posts earned DCP from eligible cash according to the active wallet streams.
     If the renewal is on-time, post the bonus as a separate event after the earned-DCP event.
     A late renewal may post earned DCP from cash if policy permits, but does not receive the on-time bonus unless an
      administrator-approved rule explicitly allows it.
     Failed, reversed or charged-back renewals must update good standing and create reversal/hold events as
      required.

5.6 Host DCPR earning from Host-attributable rental spend
     CURRENT HOST DCPR RULE: When a qualifying rental settles on a Host vehicle, the Host earns
     DCPR based on the qualifying rental spend attributable to the Host under the contractual split.
     This is a separate DCP earning event from the renter's DCP.

Current default formula (effective-dated/configurable):
     host_dcp_basis = qualifying_rental_spend × host_contractual_split_pct
     host_dcpr_earned = floor(host_dcp_basis × host_dcpr_rate)
     current default host_dcpr_rate = 10 DCP per eligible $1

     Credit the Host award to DCPR because the source activity is rental spend.
     The renter earns DCP independently under the renter's membership tier, wallet streams and live earning
      rules. Host DCPR is not transferred from, deducted from, or netted against the renter's DCP.

6.2 Redemption workflow
1.    Quote transaction and determine maximum eligible DCP based on plan, wallet and benefit caps.
2.    Validate membership status, good standing, benefit activation, inventory, agreement, insurance/risk and any
      wallet-specific eligibility.
3.    Reserve DCP before booking/approval. Reserved DCP is unavailable for other transactions.
4.    At completion, settle only the actual DCP required.
5.    Release unused reserved DCP.
6.    Post purchasing power delivered and actual Dream Carz fulfillment cost separately.
7.    Release the associated DCP accounting liability when redemption is completed.

6.3 Rental redemption priority
     DCPR is always first priority for rental savings. Black may then apply DCPE if DCPR is
     insufficient or if the member selects an approved DCPE application. Other wallets do not
     automatically substitute for DCPR.

6.4 Partial redemption
If the member has insufficient eligible DCP for the full target discount, the quote engine may calculate a partial
DCP discount if the current plan permits partial redemption. The UI must show the DCP used, remaining DCP,
cash rate after DCP, and any non-discountable charges.

7. Membership Lifecycle, Good Standing and Tenure
7.1 Membership statuses
     Pending
     Active
     Past Due
     Suspended
     Cancelled
     Expired / Archived (optional reporting state)

7.2 Good-standing evaluation
     Required membership payments are current or within approved grace period.
     Identity, agreements and required program documents are complete.
     Rental/vehicle obligations are current.
     No unresolved fraud, chargeback, default or serious policy violation exists.
     Required insurance/coverage and vehicle-specific obligations are satisfied when relevant.
Evaluate good standing daily and immediately after payment, failed payment, reversal, chargeback, default,
cure, suspension, reactivation or administrative action.

7.3 Upgrade and downgrade handling
     Plan changes must be effective-dated.
     Do not rewrite historical DCP awards or earning rules after a plan change.
     New earning events use the plan configuration effective at the event timestamp.
     Wallet access after downgrade must follow approved policy: available, held, restricted or grandfathered; do not
      silently delete balances.
     Upgrade eligibility must be checked before allowing DCPM or other benefits to reduce an upgrade transaction.

7.4 Founding member capability
The platform should retain support for a configurable Founding Member award/level tied to permanent
membership number or enrollment sequence. The current master specification does not hard-code a Founding
Member award amount. Any future award must post through the DCP ledger and be effective-dated.

8.2 Quote formula
     eligible_base = pricing_engine(vehicle, duration, market, utilization, plan)
     member_rate = apply_membership_pricing(eligible_base, member_tier)
     member_rate = max(member_rate, configured_contribution_floor_if_applicable)
     max_dcp_value = calculate_wallet_redemption(member, transaction, plan_caps)
     base_after_dcp = max(0, member_rate - max_dcp_value)
     final_cash_due = base_after_dcp + coverage + taxes + deposits + pass_through_charges


8.3 Current reference daily rate plans
Current sales materials have used three public reference options: $39.95/day with 50 miles, $49.95/day with 100
miles, and $59.95/day unlimited-mile reference pricing. These must remain configuration records, not
permanent constants. The current membership “as low as” discount ladder is based on the $49.95/day option.

8.4 Protect economics
     Do not allow membership discount + promotion + DCP to push realized economics below the approved floor
      unless an authorized subsidy budget covers the difference.
     Coverage should be calculated separately unless a specific plan rule says otherwise.
     Member pricing and Host/Partner settlement are independent calculations.
     Record subsidy amount when Dream Carz funds a member benefit below the vehicle settlement requirement.

12. Host, Partner, Associate and Commission Integration
12.1 Host / Partner settlement rule
     Member pricing and vehicle-owner settlement are separate calculations. A member discount or
     DCP redemption must not automatically reduce the Host/Partner agreed settlement.

      Member Rental Rate = what the customer is charged after membership pricing and eligible DCP.
      Vehicle Settlement Rate (VSR) = approved minimum/contractual economics for the vehicle.
      Membership Benefit Subsidy = Dream Carz-funded difference if member pricing is below required settlement
       economics.
      Host/Partner payout = calculated from the applicable agreement, independent of the member discount.
      Host DCPR = separate rental-reward calculation for eligible Host accounts, based on qualifying rental spend
       attributable to the Host under the contractual split; it does not reduce renter DCP or Host cash payout.
      DCP redemption = customer benefit, recorded separately from settlement.
      Dream Carz contribution margin = company revenue minus direct costs, payout, commissions and actual DCP
       redemption cost.

12.2 Host DCPR split rule
     HOST DCPR IS SOURCE-BASED: the Host receives DCPR because the qualifying source
     transaction is a rental. The earning basis is only the qualifying rental spend attributable to that
     Host under the contractual Dream Carz/Host split.

    Internal Development Source of Truth | Effective September 11,                                                            Page 16
    2026
DREAM CARZ | AI + DCP MASTER PROGRAMMER SPECIFICATION
     host_dcp_basis = qualifying_rental_spend × host_contractual_split_pct
     host_dcpr_earned = floor(host_dcp_basis × host_dcpr_rate)

     Example: $600 qualifying rental spend × 50% Host split = $300 Host DCP basis. At the current default 10 DCP
      per $1, the Host receives 3,000 DCPR.
     The renter's DCP and the Host's DCPR are two independent awards tied to the same rental source
      transaction.
     Host DCPR is credited to the Host DCPR wallet/account and is never deducted from the renter's wallet.
     The Host contractual split percentage and Host DCPR rate must be effective-dated configuration, not hard-
      coded.
     If a Host is also a Dream Carz member, the Host DCPR event still identifies the Host beneficiary separately
      from the renter/member beneficiary.
     Partner accounts do not receive Host DCPR unless the live agreement/configuration explicitly marks that
      account as Host-DCPR eligible.

12.3 Current Host eligibility
Current AI rule: the Host Program uses Dream Carz vehicles only. The AI must not tell customers they can place
an independently owned third-party vehicle into the Host Program unless the rule is formally changed in live

12.4 Associate and commission architecture
     Store permanent sponsor and placement genealogy.
